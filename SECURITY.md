# Security Policy

## Supported versions

| Tags | Status |
|---|---|
| The three newest Kubernetes minors (`1.37`, `1.36`, `1.35`), their current patch tags, and `latest` | :white_check_mark: rebuilt every week |
| A minor that has fallen out of the newest three, and patch tags no longer current | :x: kept, no longer rebuilt |

Fixes ship in the next build; nothing is patched in place.

## Reporting a vulnerability

Report privately through GitHub: **Security → Report a vulnerability** on this repository (private vulnerability reporting is enabled). Email to v@valdemar.ai also works. The process is described at [heyvaldemar.com/security](https://heyvaldemar.com/security/).

You can expect an acknowledgment within 7 days. This project does not operate a bounty program; researchers who submit valid, responsibly disclosed reports receive public credit in the release notes and the changelog.

Please do not open public GitHub issues for security reports. A vulnerability in kubectl itself belongs to the Kubernetes Security Response Committee (https://kubernetes.io/docs/reference/issues-security/security/); one in Debian's packages to Debian.

## Supply chain verification

Every published image digest is signed with cosign using Sigstore keyless OIDC issued to this repository's GitHub Actions workflow. SBOM (SPDX, generated by BuildKit) and SLSA build provenance are attached to every image, and build provenance is attested in GitHub Attestations. kubectl and yq are verified by sha256 before they are installed.

```bash
cosign verify heyvaldemar/kubectl:1.37 \
  --certificate-identity-regexp "https://github.com/heyvaldemar/kubectl-docker/.*" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"
```

## Credentials

The repository holds no credentials. Publishing uses the `DOCKERHUB_USERNAME` and `DOCKERHUB_TOKEN` repository secrets; signing is keyless.
